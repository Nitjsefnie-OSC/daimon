# GitHub retirement rollout

The one-shot version of migration 0105 could break an in-flight turn: it dropped schema while old MCP and worker processes could still query it. Phase 1 now retires the current legacy rows but keeps every old table and column. Old processes can complete reads and writes until their containers refresh. New code ignores late legacy keys and bindings and reads `app_visible` instead of `staged`; a trigger keeps both grant visibility columns consistent for overlapping writers. Phase 1 creates `mode='app'` rows for every agent with a retained visible grant, including grants whose installation is temporarily unusable. The same trigger creates or restores that row whenever a later grant becomes visible. The deployed worker and session preparation treat a missing row as legacy.

`CurrentOrder` violates `NoOldSchemaReadFailure` in 18 distinct states: migration contracts the schema, then an old process reads it. `DeletesModes` violates `NoLiveGrantHidden` in 18 states: expansion deletes the App mode row, then an old-worker grant write stages a live grant. `NoGrantModeUpsert` violates `NoLiveGrantHidden` in 33 states: a new MCP grant has no mode row, then an old worker stages it. `UsableOnlyBackfill` violates `NoLiveGrantHidden` in 42 states: an initially unusable grant receives no mode, its installation recovers, then an old worker stages it. `PhasedOrder` checks clean in 40 states: expansion gives every retained visible grant App mode, new visible grants upsert it, and contraction waits until MCP and workers are new and the old turn is idle. The model has one schema, one MCP revision, one worker revision, one turn, one existing grant and one initially absent grant for a different agent; the existing grant's initial mode can be App, legacy or missing, and its installation can be usable or unusable. There are no scaled numerical constants. The post-0105 migration test replays old reads and inserts, installation recovery, old mode-dependent grant writes, a new grant after migration, a new update of an old staged row, and the trigger's visibility result. Phase 2 is specified here but not implemented or deployed; the model assumes its process-version and turn-drain gate is enforced. No live deploy trace has been replayed.
